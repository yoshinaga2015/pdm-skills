# 動画のスキルのひな形

この文書は、ui-video-builder で、利用者のリポジトリ専用の動画のスキルを書くエージェントが読む。下のひな形の `<>` を、そのリポジトリの具体的な値に置き換えて、`.claude/skills/ui-video/SKILL.md` に書く。

書くときの決まり。

- ファイル名、コマンド、ポートは、そのリポジトリで実際に動くものを書く。生成の途中で流して確かめたものだけを書く
- 決まりは、破ったときの被害が大きい順に並べる。各決まりに、破ると何が起きるかと、確かめる方法を添える
- 対応表は、利用者が言う「直したいこと」の言葉から引けるようにする
- 手順には、コマンドと、終わったと言える条件を書く
- このリポジトリに当てはまらない節は消す

# ui-video — <このアプリ>の動画を台本から作る

この文書は、<このアプリ>の動画を作り直すエージェントと、字幕や台本を直したい人が読む。読み終えると、どのファイルを変えれば動画のどこが変わるかが分かり、mp4 を撮って確かめるところまで進められる。

動画は、<画面の作り方: アプリの本物のページを開き、録った通信を返し、時計を止めて1コマずつ撮る / 部品の作り方: アプリの部品に値を渡してコマごとに描き、1コマずつ撮る>。画面は録画しない。コマの番号は0から数え、1秒は<30>コマである。

## 決まり

破ると動画の中身が事実と食い違う順に並べる。

1. **同じコマは、何度撮っても同じ絵になる。** <乱数の固定、動きの同期、読み込みの待ち、毎コマ1回描かせる処理を消さない。合格試験の「同じコマ」が確かめる>
2. **数値と AI の応答の文は、アプリから持ってくる。** <録った通信の応答を使う。手で書かない>
3. **録った通信を git に入れない。** <`video/recordings/` は `.gitignore` に入っている。録るのはデモ用の利用者の、架空のデータだけ>
4. **本物の AI や外部のサービスに届く操作は、録る前に利用者に確かめる。** <何に届き、課金されるか>
5. **アプリに無い画面を、アプリの見た目で作らない。**
6. **断りや注記は、本編より目立たせない。**
<生成の途中で決めた決まりを足す>

## 置き場

| 置き場 | 中身 |
| --- | --- |
| `video/scenes/<名前>.mjs` | 場面の並び、操作、字幕、カメラ |
| `video/recordings/<名前>.json` | 録った通信。git に入れない |
| `video/shoot.mjs` | 1コマずつ撮るループ |
| `video/replay.mjs` | 録った通信を返す仕組み |
| `video/overlay.js` | ページに重ねる字幕とカメラ |
| `video/record.mjs` | 通信を録るスクリプト |
| `video/render.mjs` | 全コマを撮って mp4 にするスクリプト |
| `video/check-adapter.mjs` | 合格試験に渡す撮る関数 |
| `out/video/` | 撮ったコマと mp4。git に入れない |

## 直したいとき

| 直したいこと | 変えるファイルと値 | 一緒に直すもの |
| --- | --- | --- |
| 字幕の文 | `video/scenes/<名前>.mjs` の `captions` | なし |
| 打つ文 | `actions` の `type` の `text` | 送る文が変わるので、通信を録り直す |
| 操作の時刻 | `actions` の `at` | 場面の長さに収まるか |
| 寄る場所 | `camera` の寄る先。選択子で指す | 部品の並びが変わったら選択子を見直す |
| 場面の長さ | `scenes` の `durationInFrames` | 操作と字幕の時刻 |
| 答えが流れる速さ | `actions` の `stream` の `every`(何コマに1つ)と `perFrame`(1回にいくつ) | 場面の長さに収まるか |
| 開いた直後の動きを済ませておく | `leadFrames` | なし |
| 応答の文 | 手で書き換えない。通信を録り直す | なし |

## 手順

### 1. 準備

- アプリを起動する: `<コマンド>`。背景のタスクとして起動し、終わったらそのタスクを止める。ポートを指定してプロセスを止めない
- <ログインの状態の用意。要らなければ消す>

### 2. 通信を録る

```bash
node video/record.mjs --origin http://localhost:<ポート> --scene video/scenes/<名前>.mjs --out video/recordings/<名前>.json
```

録った後、`video/recordings/<名前>.png` を見て、操作が最後まで行われたかを確かめる。録ったファイルに、鍵や個人情報が無いかを見る。

### 3. 撮って見る

```bash
VIDEO_ORIGIN=http://localhost:<ポート> node video/render.mjs --video <名前>
```

`out/video/frames/<名前>/` のコマを、場面ごとに始め・中ほど・終わりの3枚以上見る。見る点は次のとおり。

- 打った文字と応答の文が、録ったとおりか。文字が化けていないか
- 字幕がアプリの大事な所を隠していないか。カメラが見せたい所に寄っているか
- 読み込みの途中や、空の画面が映っていないか

### 4. 合格試験を流す

```bash
VIDEO_ORIGIN=http://localhost:<ポート> node <ui-video-builder の置き場>/scripts/check.mjs --adapter video/check-adapter.mjs
```

「合格」なら終わる。「不合格」なら、仕組みの側を直す。合格試験は書き換えない。「同じコマ」が合わないときは、`<ui-video-builder の置き場>/scripts/repeat.mjs` で同じコマを何回も撮り、違う範囲を出す。

### 5. 本番のビルドに入っていないかを確かめる

`<本番のビルドのコマンド>` を流し、`grep -rl "__videoConfig" <出力の置き場>/ || echo "入っていない"` で、動画のコードが入っていないことを確かめる。<開発サーバーとビルドが同じ置き場を使うフレームワークなら、開発サーバーを止めてからビルドする、と書く>

### 6. 終える

- 合格試験の結果と、見たコマの番号を報告に書く
- 背景で起動したアプリを止める
